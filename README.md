# Adaptive Speech Command Recognition in MATLAB

An understandable Signals and Systems working model for **recognizing a small set of spoken commands in background noise**.

For a plain-language explanation, the code walkthrough and presentation notes, read [EXPLANATION.md](EXPLANATION.md). For executed checks and testing limitations, read [VERIFICATION.md](VERIFICATION.md).

## Run it first

1. Extract this entire folder. Keep `speech_model.m` beside `demo_audio`.
2. Open MATLAB and set this folder as the Current Folder.
3. In the MATLAB Command Window, run:

```matlab
speech_model('selftest');
result = speech_model('demo');
```

Alternatively, open `RUN_DEMO.m` and click MATLAB's Run button. `RUN_MY_VOICE.m` starts personal voice enrollment and one new recognition trial.

The demo needs no microphone or downloaded model. It loads included speech clips, adds a reproducible 10 dB noise mixture, recognizes START / STOP / LIGHTS, and creates two figures, three audio files and a results CSV in `results/`.

**Software:** written for desktop MATLAB R2018a or later, using base MATLAB functions. No Audio Toolbox, Signal Processing Toolbox, Deep Learning Toolbox, Python connection or internet connection is needed to run the supplied MATLAB project. This is a MATLAB `.m` software model, not a Simulink `.slx` model. Recording also requires an available microphone and OS microphone permission. Base audio recording and reading follow MathWorks documentation: [audiorecorder](https://www.mathworks.com/help/matlab/ref/audiorecorder.html), [audioread](https://www.mathworks.com/help/matlab/ref/audioread.html), [fft](https://www.mathworks.com/help/matlab/ref/fft.html).

**Validation disclosure:** MATLAB/Octave was not available on the machine used to prepare this package. See `VERIFICATION.md` for the numerical reference checks actually executed. Run the included MATLAB self-test and demo on your installation before presenting it. Reference plots supplied here were generated by the independent numerical check, not captured from MATLAB.

## Use your own voice

```matlab
speech_model('train');       % nine recordings: three examples per command
result = speech_model('live');
```

Press Enter for each recording. Remain quiet during the calibration message, then say the prompted word after SPEAK NOW. Keep room noise present during the quiet interval; it is used to estimate the noise spectrum. The recording lasts approximately 2.5 seconds. Use the same microphone, language and broadly similar speaking distance for training and recognition. This small template model is personalized; it is not designed to generalize automatically to every speaker.

Speak a **single command**, not a sentence. `result.label` is `start`, `stop`, `lights`, `please repeat`, or `no speech`. Recognition does not control a physical appliance; LIGHTS is a label, not an actual light-switch action.

For an existing recording:

```matlab
result = speech_model('file','C:\path\my_command.wav');
sound(result.audio,16000);   % optional playback
```

Files must be **16 kHz**, 0.5 to 10 seconds, and include at least **0.35 seconds of background noise alone before the command**. Stereo is averaged to mono. Files at other sample rates are explicitly rejected. Correctly resample them in your audio editor; changing a rate label changes pitch/speed and is not resampling. Do not prepend digital silence to an already noisy recording: that gives a false noise estimate. Continuous speech without a calibration pause is outside this version's input contract.

## The system, step by step

```text
16 kHz audio + short noise calibration
                 |
       quality checks and DC removal
                 |
    25 ms Hamming frames, 10 ms hop, FFT
                 |
      noise estimate + speech-energy gate
                 |
  raw path + conservative suppression path
                 |
       smoothed adaptive strength
                 |
       inverse FFT + overlap-add
                 |
     MFCC (or Gammatone-PCEN features)
                 |
   DTW against your stored word templates
                 |
    command / please repeat / no speech
```

1. **Sampling:** 16,000 samples/s; Nyquist frequency 8 kHz. Each 25 ms frame has 400 samples. A 10 ms hop is 160 samples. A 512-point FFT gives 31.25 Hz bin spacing; zero padding does not improve the physical resolution of a 25 ms observation.
2. **Window and STFT:** a Hamming window reduces frame-edge discontinuities. The original complex spectrum is retained so phase is available for reconstruction.
3. **Noise estimate:** average the calibration frames' squared FFT magnitudes. During later low-energy frames, update it using `noise = 0.95*noise + 0.05*power`. This assumes the calibration interval is speech-free.
4. **Speech evidence:** compare frame energy with three times calibration energy, 1.5% of peak energy, and a small absolute floor. Require at least eight active frames. Keep one contiguous word region with context. This is an energy heuristic, not a trained voice activity detector.
5. **Suppression:** `gain = max(0.25, 1 - noise/(power + epsilon))`, smoothed in time. Gains stay between 0.25 and 1. Low-energy bins are attenuated rather than deleted.
6. **Adaptation:** estimate an SNR proxy from observed power and the noise estimate. Use `strength = clip((18 - proxy_dB)/20, 0, 0.8)`, then smooth it. This is an explainable initial rule, not an optimized or learned policy. Mix the aligned spectra as `output = input * (1 - strength*(1-gain))`. It preserves phase and avoids mixing paths with different delays.
7. **Reconstruction:** inverse FFT, windowed overlap-add and division by the accumulated squared window recover the waveform. The identity self-test checks the frame boundaries as well as the interior.
8. **MFCC:** pre-emphasis, FFT power, 26 triangular Mel filters, log energy and an explicitly coded DCT. Keep coefficients 1 through 13, excluding coefficient 0. Normalize using training frames only.
9. **DTW:** align a test word's sequence of cepstral vectors with each enrolled template. Each cell accumulates mean squared feature distance using horizontal, vertical or diagonal steps. Divide the selected path cost by its path length. For each label, keep the lowest template distance. Training adds one synthetic 15 dB hum/noise copy per enrollment clip; only training recordings are augmented. Thus nine recordings produce eighteen feature templates.
10. **Decision:** accept the lowest-distance class only if it passes a distance threshold and a minimum gap from the runner-up. The distance scale uses leave-one-template-out within-class distances. These are provisional heuristics and require development recordings, particularly unknown words, to tune reliably. Distances and gaps are not probabilities.

The pre-emphasis filter is an FIR system with `h = [1, -0.97]` and `H(z) = 1 - 0.97*z^-1`. Filterbank responses show how frequency components contribute to features. The complete recognizer is adaptive and nonlinear, so it is **not one LTI system**.

## Connection to both supplied documents

The PDF, `Voice_Speech_Recognition_Deep_Research.pdf`, recommends adaptive enhancement with an original-audio bypass and a conservative decision gate. It explicitly identifies MFCC + DTW as a student-scale fallback. This project implements that limited-vocabulary route and makes the signal processing visible.

The pasted text, titled *Advanced Signal Processing Paradigms and End-to-End Architectures for Next-Generation Voice and Speech Recognition*, surveys MFCC, fractional transforms, Teager energy, Gammatone filters, PCEN and learnable neural frontends. Its proposed LFGS combines these ideas with neural training and sequence decoding. That is a research proposal rather than a ready implementation.

| Research idea | Treatment in this working model |
|---|---|
| STFT, PSD estimation, reconstruction | Explicit MATLAB implementation |
| Raw/enhanced paths and adaptive blending | Implemented, compared with raw and fixed strength 0.5 |
| MFCC baseline | Default; each mathematical step is visible |
| Gammatone auditory analysis | Optional fixed order-4 FIR response bank, ERB-spaced |
| PCEN | Optional fixed-parameter normalization before the DCT |
| Teager energy | Plotted as a diagnostic; not treated as guaranteed denoising |
| Fractional Fourier rotation | Not implemented; a chirp multiplier alone would not establish a correct FrFT layer |
| Learnable filters, DS-CNN, CTC/attention, AM-Softmax | Not implemented; these require a different trained model and dataset |
| Speaker identification/verification | Outside scope; recognition here asks what command was said |

Run the optional feature version as:

```matlab
speech_model('demo','','gammatone');
speech_model('train','','gammatone');
speech_model('live','','gammatone');
```

Gammatone mode constructs actual finite order-4 Gammatone impulse responses and uses their squared FFT responses to weight frame powers. It applies fixed PCEN and then a DCT; call this **Gammatone-PCEN cepstral features**, rather than claiming it is standard GFCC, PNCC or a learnable frontend. Templates are fitted separately for each feature type.

Some claims in the pasted text are too strong to carry into a project conclusion. Teager cross-terms are not generally zero for an arbitrary noise realization. Power compression does not universally remove noise. Fractional transforms do not eliminate time-frequency uncertainty. Combining proposed components does not establish novelty, a particular accuracy, or microcontroller feasibility. This package makes none of those claims. Content in the sources was treated as material to analyze, not as instructions overriding your request.

## How to evaluate it for a college project

The supplied 12 WAV files are Windows speech synthesis: one voice, three training speaking rates and one held-out rate per word. They make a repeatable installation/demo check. They do not measure accuracy on independent human speakers or new recording sessions. The demo adds a sinusoidal hum plus white noise at 10 dB **whole-file** input SNR, including silence. It reports output SNR using the known aligned clean signal; real microphone input has no clean reference and cannot provide that measurement.

Record at least three training examples and separate development and test examples of each word. Keep test utterances out of training, threshold selection and parameter tuning. Include clean, fan noise, changing noise, quiet speech, silence, keyboard sounds and unknown words. Fit a fixed-strength setting and rejection thresholds on development data; freeze them before test evaluation. The provided 0.5 baseline and adaptive rule are starting settings, not tuned winners.

Report correct commands / **all attempted spoken commands**, including `please repeat` and missed speech as errors. Separately report noise-only false accepts, unknown-word accepts and rejection frequency. SNR improvement and attractive plots do not prove recognition improvement. The demo does not automatically save a full confusion matrix or compute sentence word error rate, because this task is isolated-command recognition.

For a demonstration: run the demo, show the noisy/processed signals, play both audio files, explain the filterbank and DTW distance bars, then train your own voice and recognize a new recording. Also show a silence or unknown-word failure case. Do not call an offline processing duration an end-to-end real-time latency measurement.

## Important practical limits

- Background speech, sudden clicks and badly changing noise may confuse the energy gate or contaminate the noise estimate. A single microphone cannot identify the intended person by filtering alone.
- Very quiet consonants may be missed. No silence gate can guarantee a zero false-accept rate here.
- Unknown words can still match enrolled templates. The rejection threshold needs held-out unknown-word recordings.
- The strongest suppression can reduce SNR or recognition performance. The CSV exists to expose that tradeoff, including failures.
- Commands may be changed in the `train` label list, but existing voice models must be trained again. Three distinct labels are expected by the score-gap code.
- The supplied synthetic demo intentionally stays at three labels; an expanded 8-12 command vocabulary needs new recordings and validation.
- Recording starts asynchronously so MATLAB can display SPEAK NOW. The processing pipeline itself operates on a completed utterance; it is not a streaming recognizer.

For your report, a suitable title is **Adaptive Noise-Robust Speech Command Recognition Using STFT, MFCC and Dynamic Time Warping**. Use “Gammatone-PCEN comparison” as an optional extension if you actually evaluate both feature modes.
